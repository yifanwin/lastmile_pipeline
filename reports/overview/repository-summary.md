# Lastmile 管线实现总结

更新日期：2026-10-02。本文根据当前代码、阶段文档和已保存的 case 记录整理。

## 1. 当前实现到了哪里

**本仓库已经打通一个 Case 1 距离型案例的六阶段半自动流程：恢复场景 → 人工审阅 → 验证稳定抓法 → 建立粗站位图 → 构造困难起点 → 连续导航抓取 → 人工接受与导出。**

目前已交付的案例是 `case1-cup-001`：episode 14、house 103、桌面目标 `Cup_30`。只改变机器人初始底盘位姿，从困难起点 P131 导航到成功站位 A 附近，再连续抓取，**3 次新仿真试验全部严格通过**，已有人工接受记录和正式导出包。

这是一套依赖已审计来源、物理证据和人工决定的构造工具，**还不是面向任意场景、任意物体的全自动批量数据生成系统**。

## 2. 六个阶段的功能与当前结果

| 阶段 | 已实现的功能 | 当前案例结果 |
|---|---|---|
| 1. 场景恢复与审阅 | 恢复物体、机器人关节和相机；保存模型及完整快照；生成四视图与交互审阅卡；人工批准/拒绝 | 恢复完成，人工批准 north/south/west 三个操作桌边 |
| 2. A 点稳定抓法 | 复核旧稳定性轨迹；在当前恢复模型上新执行抓取；冻结抓法与验收协议 | 历史名义 **5/5**、扰动 **20/20** 通过；新 A 点试验 **1/1** 通过 |
| 3. 粗站位图 | 采样底盘位置和朝向；几何过滤；双臂 × 五个躯干高度规划；关键点真实抓取；图表及证据审计 | **172** 个位姿、**58** 个 XY 位置；完成规划与 **12** 次物理尝试 |
| 4. 困难起点构造 | 原始起点筛选；仅移动机器人起点的 `robot_only` 分支；范围证书、可见性和状态一致性检查 | 原始 A 点因可成功抓取被筛除；选择超范围 P131，只改初始 base |
| 5. 连续导航与抓取 | A* 导航、实测到站、无重置抓取、重复验收、原轨迹审计和视频回放 | `astar_v2` 完成 **3/3** 次新闭环试验，严格验收通过 |
| 6. 最终接受与导出 | 最终审阅包、人工决定、导出门禁、草稿/正式包、文件校验与保存状态回放 | `final_v2` 已人工接受并正式导出 |

### 阶段 1：恢复真实场景，而不是只摆放目标

- 校验 episode、源场景、资产及 grasp 的来源；不允许跳过缺失物体。
- 恢复房屋、额外资产、全部物体位姿、机器人初始关节及 benchmark 相机。
- 保存独立编译模型 `compiled_model.mjb`、初始快照 `initial_snapshot.npz` 和场景事实。
- 生成俯视图、机器人初始视图、目标近景、桌边提示图。目标标框来自实例分割。
- 支持本机网页审阅与离线 JSON 导入；人工决定绑定审阅包摘要，证据改变后批准失效。
- 可调用配置的 LLM API 给出场景建议，但 agent 没有批准权。

桌边提示只说明几何关系，不证明机器人已经能够导航或绕行。

### 阶段 2：建立可复核的成功站位 A

当前冻结抓法为左臂、躯干高度 `h=0.738`、资产 grasp 第 `794` 行。利用实际场景碰撞几何，经 cuRobo 规划后执行躯干调整、预抓取、接近、闭合、抬升和保持。

稳定性证据明确分为两类：旧校准数据重新验收，以及当前模型的新 A 点实跑。**旧 25 次轨迹不是本轮新增试验**，也不用于直接证明其他站位或导航成功。

支持人工审阅前预校准，但只能得到暂定物理通过状态，不能绕过人工批准进入站位图阶段。

### 阶段 3：把“几何、规划、实际抓取”分开标注

在批准的桌边操作带采样包含朝向的底盘位姿，先检查地面、初始碰撞和保守接触距离上界，再检查双臂及五个合法躯干高度的路径。

当前 `coarse_v1` 的保存结果为：

| 项目 | 数量 | 含义 |
|---|---:|---|
| 几何筛选合格位姿 | 72 | 可以继续规划，不等于可抓取 |
| 初始碰撞位姿 | 74 | 初始机器人姿态与环境冲突 |
| 接触上界之外位姿 | 26 | 超过保守接触范围 |
| 规划查询 | 720 | 72 个位姿 × 双臂 × 五个高度 |
| 完整路径规划通过 | 41 | 对应 13 个底盘位姿，不等于实际成功 |
| 搜索预算耗尽 | 679 | 不证明连续状态空间不可达 |
| 物理尝试 | 12 | 9 次成功、1 次完整抓取失败、2 次未完成 |

各点从同一原始快照独立初始化，仅放置机器人底盘；这不是导航。只有完整动态抓取才给出成功/失败二值标签，未完成的尝试不强行算作失败。

输出 PNG/SVG/HTML 站位图、含朝向的 CSV/JSON 明细及局部高斯插值。插值只使用完整物理标签，未知区域保持未知；它不是重复试验成功率，也不是导航真值地图。

### 阶段 4：保留原样筛选历史，再构造机器人困难起点

已实现两条分支：

- **`original_only`**：不改场景，复核原始起点是否已有符合协议的抓取成功证据。episode 14 原始 A 点可成功抓取，因此不能作为困难失败起点。
- **`robot_only`**：从站位图中的超范围候选选择新初始 base，保持目标、家具及其他初始关节和速度不变；保存修改清单和派生快照。

当前 P131 距目标约 **1.557 m**，保守接触上界约 **1.217 m**，超出约 **0.339 m**；目标在初始 head_camera 中可见。

起点“原地抓不到”的依据是覆盖双臂、全朝向和连续合法躯干范围的保守接触上界，**不是伪造一次伸臂失败动作**。有限规划预算无解不会被升级成不可达证书。

### 阶段 5：导航后直接使用实际到站状态抓取

- 按完整机器人身体碰撞几何构建保守导航网格，包含头和双臂，不只使用一个底盘圆盘。
- A* 禁止对角穿角，路径简化继续检查自由空间。
- 先到安全停靠点，实际转向，再接近 A；导航通过仿真中的底盘控制执行。
- 导航时固定头和双臂、保持躯干初始高度，检查禁止碰撞及目标位姿变化。
- 保存实际到站快照，之后不恢复原始状态，连续进行躯干调整、重新规划和抓取。
- 按 0.004 s 记录导航状态；重复试验遇失败即停止并保留证据。
- 视频回放保存的真实关节状态，不合成或插值运动；墙体透明仅用于渲染展示。

当前案例分类是 **Case 1-R：同侧平移可解决**。没有证明必须换桌边，也没有证明整条西侧都无法操作。

### 阶段 6：人工接受与可追溯导出

生成不可覆盖的最终审阅包，接受 `accepted / rejected / reconstruct` 人工决定。只有有效人工接受且物理证据满足要求，才可正式导出；未接受的草稿明确标记为不准入数据集。

正式包按白名单收集来源、修改清单、模型、快照、协议、站位图、三次完整轨迹、接触判定、视频、审阅材料和实现/环境记录，不包含凭据或 Git 元数据。

支持文件 SHA-256 校验和包内保存状态回放。**保存状态回放不是重新执行动力学仿真**；重新运行 cuRobo 仍需要原工程资产、GPU 和对应依赖。

## 3. 已实现的底层支撑

- **动作协议**：规定底盘、双臂、夹爪和联动躯干的动作布局、高度范围及约束。
- **严格 Pick 验收**：检查正确目标、双指真实受力接触、至少抬升 **5 cm**、无支撑连续保持至少 **2 s**、相对位姿稳定及禁止碰撞；同时约束底盘、躯干、头和闲置臂。
- **来源与证据审计**：冻结配置、模型、协议、人工决定和轨迹摘要；从原始轨迹重新判定，不只读取 `success` 字段。
- **状态与续跑**：按 case manifest 记录六阶段状态，按 run-id 保存运行；站位图支持冻结输入不变时续跑。
- **交互展示**：本机审阅服务、离线审阅页、站位图页面及闭环视频。
- **部件语义基础**：已有把手区域接触、禁止部件、直立约束和抓法过滤工具，但不等于 Case 2 完整工作流已经可用。

## 5. 尚未实现或不能据此声称的内容

1. **任意 episode / 资产的通用接入与批量筛选**：当前公共恢复、稳定证据和站位图路径围绕已审计 episode 14 / Cup_30 实现，新来源仍需扩展审计与校准。
2. **移动目标、调整家具等完整构造分支**：当前完成的是原样筛选及只改机器人 base；其他修改方式不是永久禁止，而是尚未实现完整流程。
3. **Case 2 把手案例端到端构造**：有底层语义检查，缺少公共工作流和人工部件确认闭环。
4. **训练 episode / RGB-D 数据集自动生成**：当前站位图阶段不生成这类训练数据。
5. **整个桌边或全部连续位姿的可达性结论**：粗采样和有限搜索只能描述已检查配置；只有实际执行点有物理标签。
6. **必须绕桌换边的困难案例**：当前验证的是同侧平移解决的 Case 1-R。
7. **真实机器人验证和广泛泛化能力**：当前成果属于 MuJoCo 仿真，不代表硬件执行或跨场景性能已验证。

## 6. 使用入口与测试

从本仓库根目录执行：

```bash
./bin/lastmile --help
./bin/lastmile status --case-id case1-cup-001

MPLCONFIGDIR=/tmp/lastmile_mpl PYTHONPATH=src \
  ../molmospaces/.venv/bin/python -m unittest discover -s tests -v
```

命令入口复用相邻 `molmospaces/setup_env.sh` 和虚拟环境，默认 CUDA 5。已有交付 run 不应覆盖，新实验使用新的 case-id / run-id / review-id / export-id。

当前单元测试覆盖协议与抓取判定、人工门禁和证据篡改、站位图标签、困难起点、导航、最终接受及导出等逻辑。2026-10-02 检查时 **100 项测试全部通过**；不把单元测试当作新增物理试验。
